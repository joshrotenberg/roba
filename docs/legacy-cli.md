# Legacy Claude CLI

The original bare `roba PROMPT` command remains a supported compatibility
surface over `claude -p`. It is Claude-specific and separate from the
provider-neutral `roba run` and hot `roba serve` paths.

This guide documents the compatibility concepts and stable scripting contract.
The complete flag, environment, and configuration reference is generated by
`roba --help`.

## What it adds to `claude -p`

- **Composable input:** `-f`, piped stdin, `-e`, `--prepend`, `--append`,
  `--attach`, Git context flags, and template variables.
- **Pipe-clean output:** stdout is the answer; metadata and diagnostics use
  stderr.
- **TTY rendering:** Markdown, spinner, color, `--plain`, and `NO_COLOR`.
- **Session re-entry:** `-c`, `--fork`, `--pick`, `--session-id`, named
  sessions, `history`, and `last`.
- **Read-only inspection:** `show`, `cost`, `doctor`, `jobs`, `watch`, and
  `worktree list`.
- **Stable scripting:** versioned JSON envelopes and typed exit codes.

## Quick examples

```bash
roba "what is the difference between Arc and Rc?"
roba --prepend system.md "review this design" --append context.md
roba --attach 'src/**/*.rs' "is the error handling consistent?"
roba --readonly --git-diff "is this safe to merge?"

# Continue the most recent session. Pass the prompt explicitly because -c
# accepts an optional session identifier.
roba -c -p "now show me how to test the unsafe variant"

# Mint a stable session id for scripted re-entry.
uuid=$(uuidgen)
roba --session-id "$uuid" "start a refactor plan"
roba -c="$uuid" "now do step 1"

# Pipe-friendly input and output.
roba "what is 2+2" -q
echo "summarize this" | roba
cat err.log | roba "what is wrong here?"
```

`-c` and `-w` accept optional values. A word immediately following either
flag is consumed as that value. Use `-p` to disambiguate a prompt:
`roba -c -p "follow up"`.

## Permission model

The compatibility command begins read-only: Claude may use `Read`, `Glob`, and
`Grep`. More authority is explicit:

```bash
roba "explain this"                       # read-only default
roba --writable "rename foo to bar"       # add Edit and Write
roba --allow-tool 'Bash(git:*)' "..."     # allow one pattern
roba --deny-tool WebFetch "..."           # deny wins
roba --add-dir ../shared "..."            # widen file-tool scope
roba --full-auto "..."                    # bypass provider checks
roba --show-permissions --profile review  # inspect the resolved set
```

`--permission-mode` controls Claude's approval posture independently of the
allowlist. Configuration precedence is CLI, then `ROBA_*` environment, named
profile, top-level config, and finally built-in defaults. Deny always wins over
allow.

To add user-supplied MCP servers to one Claude invocation:

```bash
roba --mcp-config mcp.json "..."
roba --mcp-config mcp.json --strict-mcp-config "..."
```

This flag forwards configuration to Claude. It is unrelated to Roba's own MCP
harness and `roba serve`.

## Profiles, aliases, and personas

Legacy configuration is discovered by walking up from the cwd and then
including `~/.config/roba.toml`. Closer files win per key. This pool does not
apply to `roba run` or `roba serve`.

- Profiles are named bundles of defaults selected with `--profile NAME`.
  A profile named `default` applies automatically.
- Aliases are verbs whose prompt templates accept positional or named values
  and optional shell substitution.
- A persona is the compatibility view of a profile that selects Claude's
  native `agent` field.

Generate validated blocks with `roba alias draft`, `roba profile draft`, or
`roba config init`. Inspect resolution with `roba config show`,
`roba config show --sources`, `roba config lint`, `roba profile`, `roba alias`,
and `roba persona`.

The fully commented [`roba-config.sample.toml`](../roba-config.sample.toml)
documents every key. Ready-to-copy configurations live in [`examples/`](../examples/):

- [`roba-reviewer.toml`](../examples/roba-reviewer.toml) -- an enforced
  read-only reviewer;
- [`roba-rust-dispatch.toml`](../examples/roba-rust-dispatch.toml) -- a
  worker-dispatch profile and aliases;
- [`roba-multi-task-worker.toml`](../examples/roba-multi-task-worker.toml) --
  one-turn, multiple-task sizing;
- [`roba-worker-lifecycle.toml`](../examples/roba-worker-lifecycle.toml) -- an
  externally driven issue lifecycle.

The starter, repository config, and every tracked example pass the real parser
and semantic linter in CI.

## Sealed runs

An ordinary Claude invocation inherits both Roba's discovered configuration
and Claude's ambient user/project context. Seal either axis or both when a run
must be reproducible:

```bash
roba --setting-sources user "..."  # keep only Claude user settings
roba --hermetic "..."              # seal Roba and Claude ambient context
roba --hermetic=roba "..."         # seal one axis: roba or claude
roba --bundle path/.roba "..."     # supply an explicit bundle
```

Under `--hermetic`, a `./.roba` bundle is the sole Roba configuration source,
MCP is strict to the bundle, and Claude's dynamic system-prompt sections are
excluded. Adding `--setting-sources user` deliberately restores global Claude
configuration.

A bundle may contain `roba.toml`, `system-prompt.md`, `mcp.json`,
`settings.json`, `agents/*.md`, and manifested plugins or skills. Roba copies
the bundle into a private run-local snapshot and validates required JSON,
agent fields, manifests, and file types before provider work.

Inspect the plan without starting Claude:

```bash
roba bundle inspect path/.roba
roba bundle inspect path/.roba --json
```

Inspection deliberately omits prompt bodies, hook commands, environment
values, and MCP command details. Snapshotting prevents later mutation of the
original from changing the run, but it is not OS isolation: trusted same-user
processes may still access the private copy. Keep the source trusted and
quiescent during capture.

## For agents and scripts

The stable stream contract is: stdout is the answer, stderr is metadata and
diagnostics. With `--json`, outputs use versioned envelopes:

```text
success: { "version": 1, "result": { ... }, "refusal": bool }
failure: { "version": 1, "error": { kind, message, exit_code, chain } }
```

Read-only reporting commands use the same `{ version, result }` shape.
`roba show` reconstructs the ask envelope, including `refusal`.

| Fact | Contract |
| --- | --- |
| Answer | `.result.result` |
| Structured answer | `.result.structured_output` |
| Metrics | Provider metrics remain nested under `.result` |
| Refusal | Exits `0`; inspect the top-level `refusal` field |
| Optional keys | `see_also` and unreported telemetry may be absent |

The common metric paths are `.result.duration_ms`, `.result.num_turns`, and
`.result.total_cost_usd`.

```bash
out=$(roba --json "...")
printf '%s' "$out" | jq -r '.result.result'
```

### Exit codes

| Code | Meaning | Typical unattended response |
| --- | --- | --- |
| `0` | Success, including refusals | Validate `refusal` and content |
| `1` | Generic or provider failure | Fail the job |
| `2` | Authentication | Fail loudly; do not retry blindly |
| `3` | Wrapper budget tracker | Fail the job |
| `4` | Wall-clock timeout | Retry or escalate |
| `5` | Maximum turns | Inspect recoverable work |
| `6` | No usable output | Treat as failure |
| `7` | Maximum budget | Inspect recoverable work |

Exit `6` is special: an empty or provider-error result may already have emitted
a success-shaped result envelope on stdout, while a stream that never produced
a result event leaves stdout empty. It does not emit a second stderr error
envelope. Branch on the exit code, then inspect stdout when present.

### Unattended controls

| Flag | Purpose |
| --- | --- |
| `--json-schema PATH` | Require schema-valid structured output |
| `--max-turns N` | Bound provider turns; exit `5` on the cap |
| `--max-budget-usd USD` | Bound spend; exit `7` on the cap |
| `--timeout SECS` | Bound wall-clock time and kill the child; exit `4` |
| `--no-retry` | Give retry ownership to the caller |
| `--trace PATH` | Preserve provider events as JSONL |
| `--fallback-model MODEL` | Retry overload on another model |
| `--no-session-persistence` | Avoid writing a resumable session |
| `--bare` | Disable ambient Claude customization for reproducibility |
| `--safe-mode` | Disable customization for untrusted input |

Use all three caps for unattended work: turns and budget bound work, while
timeout alone catches a child that hangs without making progress. A minimal
guard is:

```bash
out=$(roba --bare --json --max-turns 80 --max-budget-usd 10 --timeout 600 \
  --trace "runs/$(date +%Y%m%dT%H%M%S).jsonl" -f task.md)
code=$?
if [ "$code" -ne 0 ]; then
  echo "roba failed: exit $code" >&2
  exit "$code"
fi
answer=$(printf '%s' "$out" | jq -er '.result.result') || {
  echo "empty answer" >&2
  exit 1
}
```

When a prompt contains untrusted issue, diff, or web content and the run has
write authority, `--safe-mode` reduces the provider customization surface.
It is distinct from `--bare`, which targets reproducibility, and may be used
together.

## Sessions and detached work

A legacy invocation is one `claude -p` turn. That turn may work through many
tasks synchronously, but it cannot end, wait in the background, and wake itself
for another turn. Size turn and budget caps for the whole batch.

Use a stable session identifier rather than bare `-c` in automation. The most
recent session can change when another invocation runs in the same project.

To hand a run off to the operating system:

```bash
id=$(roba --detach --profile worker -C <dir> -f task.md \
  --trace /tmp/roba-trace.jsonl)
roba show "$id" --wait --timeout 600
```

The minted handle is the only stdout output. Roba verifies the provider binary
before detaching and refuses piped data that the child would lose. Pair detached
work with explicit turn, budget, and time rails.

Detached runs write receipts under `$ROBA_STATE_DIR/runs`, then
`$XDG_STATE_HOME/roba/runs`, then `~/.local/state/roba/runs`. A receipt records
the typed exit code and provider-reported cost when known. `show --wait` uses it
to reproduce failure status instead of guessing from session logs.

```bash
roba jobs                 # inspect detached receipts
roba watch                # wait for every running receipt
roba watch 43a14535 9f2b  # wait for selected unique prefixes
```

A `stale?` receipt means the recorded process disappeared before writing its
terminal state. Receipts older than roughly 30 days are pruned when a new
detached run begins.

If an external workflow needs several phases, it must own that sequence. The
compatibility command is the finite worker, not a scheduler. The example
[`roba-worker-lifecycle.toml`](../examples/roba-worker-lifecycle.toml) shows
profiles and aliases for an externally driven plan, implementation, review,
and merge process.

## Skills and agents

Roba does not bundle a skill or agent library. Claude discovers user-managed
skills and agents through its own configuration. Sealed bundles may carry an
explicit task-scoped set when ambient discovery is undesirable.
